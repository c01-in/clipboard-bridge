# 0.2.2 preview — send to computer, without clock matching

Open a document with **Send to computer**, or choose the same action from Android Share. This update also replaces phone/PC clock comparisons for file transfers with sessions issued and timed by the computer.

- **Android Open with:** PDFs, images, videos and other selected files go to the computer's receiving folder, including a single image or text document. Only the selected content URI's read permission is forwarded; web links and raw filesystem paths are excluded.
- **Clearer actions:** Android Share and Open with use the localized **Send to computer** label in all nine languages. The launcher keeps its app name. Samsung's system panels display the application name above the action label.
- **Clipboard rules stay explicit:** sharing one image uses the computer clipboard; shared plain text still waits for a Send tap. Multiple images and file attachments are saved as files. Open with always saves a file.
- **File sessions:** the computer issues an authenticated session and measures its expiry with its own elapsed-time clock. The new file protocol does not require the phone and PC clocks to match. Update both endpoints; older Android clients retain their legacy compatibility path. Clipboard messages retain their existing expiry checks.
- **Interrupted uploads:** a new deliberate send can replace an incomplete upload after two minutes without accepted progress. Active uploads and fully uploaded batches awaiting desktop saving remain protected, including across broker restarts.
- **Useful errors:** an HTTP rejection is reported separately from an unreachable computer, including when another saved address is offline.
- **Windows tray and settings:** pause and manual sending are easier to reach; the manual shortcut is shown. Closing settings exits the tray app, minimizing hides it to the tray, and background startup does not open settings automatically.

Existing pairing and pause preferences are preserved by an in-place update within the same distribution channel. No account, Firebase project, credential import, root or phone debugging is needed for normal use. Android still requires Google Play services and access to Google's network for push.

## Verification and availability

The release functionality was checked on a Samsung Fold in owner user 0 using the existing pairing: a selected PDF fixture reached Windows with identical SHA-256; a shared PNG reached the Windows clipboard with its original transparency; shared Unicode text and emoji matched after the Send tap. Eight Android routing/resolver/read-grant checks passed. The source CI passed Android compilation/lint and 153 Windows protocol, pairing, localization and download checks. These checks do not claim that every Android file manager or long-sleep push condition was tested.

GitHub publication, Google Play review and Microsoft Store certification are separate. A GitHub release does not establish store approval. The online installer downloads the currently available Store version; the complete MSIX is attached only after the matching 0.2.2.0 package appears in Microsoft's public catalog.
