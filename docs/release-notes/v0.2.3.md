# 0.2.3 preview — Windows home page and clearer receive notifications

- Android's single-image Share action is now **Copy to PC** (复制到电脑), with shorter labels in all nine languages. It writes the image to the computer clipboard.
- Received-file notifications provide **Open file** and **Show location** for one file. Tapping the notification also offers both choices. Multiple-file batches provide **Show location**.
- Each received batch has its own notification. Opening the app or another transfer no longer clears unrelated results. Users can dismiss notifications themselves.
- Windows now has separate **Home** and **Settings** tabs. Home provides clipboard sending, file sending, pause, the receiving folder, and the phone-app download. Settings contains pairing and the receiving-folder preference. The version remains at the bottom.
- File sending keeps its existing rules: Windows Share, Send to and the file picker save files on Android, including a single image. Android Open with and Send files save files on Windows. Clipboard copying remains a separate route.
- Maintainers have one **Publish** workflow: one cloud test/build, GitHub downloads, then both store submissions. Local development builds remain available; no local release build or pre-commit CI is required.

Existing pairing is preserved by in-place updates within the same distribution channel. File transfers continue to use PC-issued, PC-timed sessions; clipboard expiry checks are unchanged. Google Play services and Google network access remain required. No app account or Firebase project setup is needed.

## Verification and availability

The preceding notification-action and routing changes passed 13 Android runtime checks in a cloud emulator before this notification-retention correction. This release's cloud workflow checks current source and builds both applications. The locally installed review build is for hands-on testing, not the source of public release binaries. Store submission, certification and public availability are separate states.

Windows Explorer can retain a generic document icon in its quick Share submenu after an update. The 0.2.3 image resources and resource index are correct; refreshing Explorer's process clears the stale share-target icon cache. This was verified in the actual right-click submenu with both the Store edition and the desktop Share integration. If the old icon persists after updating, restart Windows Explorer from Task Manager when file operations have finished, or sign out and back in. Reinstalling the app alone may leave the existing Explorer process's cache unchanged.
