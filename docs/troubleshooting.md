# 故障排查

## 下载完成仍卡住

优先使用 README 的 GitHub HTTPS 链接。局域网 APK 路由支持 GET、HEAD、Range 和基于实际 SHA-256 的 ETag；取消旧任务后重新下载。下载成功不代表已经覆盖安装，请核对 App“关于”的版本。

## 手机找不到电脑

两端使用匹配版本，打开 Windows 设置和手机 App。0.2.0 文件功能需要两端都是 0.2.0；Windows 版可从[微软商店](https://apps.microsoft.com/detail/9PJT9PTSMCJQ)获取。电脑的可发现窗口为 120 秒，到期点击“搜索手机”。检查同一 Wi-Fi、AP 客户端隔离、UDP 45872 防火墙和 VPN 路由。
首次配对无需输入地址或 Firebase 文件。确认两端同一六位代码。已有设备通过认证发现更新地址；更换电脑位于手机更多菜单。
Tailscale 不转发普通 Wi-Fi 广播，首次请在同一子网配对，再添加备用地址。

## 正在恢复／注册失败

更新 Windows 后再更新 Android，打开手机 App 一次。旧配对会通过加密请求取得 Windows VAPID 公钥；无需重配。若电脑离线，恢复暂不能完成。
检查两端到 Google 的网络、手机 Google Play 服务及 TCP 45871 可达性。没有 Firebase 文件是正常状态，不要导入旧服务账号来修复新版本。
检查手机的通知权限与“剪贴板同步”开关。Google 的 HTTP 成功不代表手机实际收到，必须查看 Windows 的写入确认。

## 暂停后不发送

手机关闭“剪贴板同步”会暂停两个方向，发送按钮禁用，Windows 显示手机已暂停。恢复后仅同步新的复制内容，不补写旧的排队更新。
暂停状态在 App 和设备重启后保留。恢复时电脑需要在线确认新的接收会话。
Windows 自己的托盘暂停只影响自动发送；手动发送仍受手机暂停约束。

## 有推送但图片不能粘贴

长文字和图片需要手机能通过局域网／Tailscale连接电脑。Windows 应保持开机、服务运行且对应地址可达。
App 对大小、SHA-256 和格式校验后才写入；单张图片最大 16 MiB。粘贴目标 App 需要支持图片 URI 剪贴板。

## Android 发给 Windows 失败

打开手机 App 后点击发送，不在后台读取剪贴板。检查手机同步开启、Windows 托盘程序正在登录用户的桌面会话运行。
服务只保存排队内容；实际剪贴板写入由托盘 STA 线程完成。手机收到带匹配 ID 的加密成功回执后才显示成功。

## Windows 后台服务未运行

先区分渠道：下述管理员安装器用于独立桌面版。微软商店 0.2.0 版使用每用户后台，不安装管理员系统服务；该版尚在认证中，当前无法从商店公开下载。切换渠道需重新配对，不要通过删除原配置试错，也不要同时运行两个占用相同端口的后台。

以管理员权限重新执行公开安装 EXE。安装器保留既有数据目录并显示真实失败；日志在 `%LOCALAPPDATA%\ClipboardBridge\install.log`。
日常桌面用户应与安装时绑定的用户一致。若服务看似正常但 IPC 不通，检查安装用户和日志，不要删除配置试错。

## 文件找不到／保存路径在哪

0.2.0 的 Windows 设置中直接显示“接收文件保存到”，点击“更改文件夹”。默认是当前用户的下载文件夹，托盘菜单也可打开接收目录；Android 10+ 默认是 Downloads/Clipboard Bridge，Android 8–9 先选接收文件夹。选定文件夹后，新批次使用新路径，已规划的批次保持原目的地。

单张图片通过“发送到剪贴板”入口或其他 App 的单图分享进入剪贴板；“发送文件”入口即使只选一张图片也保存为文件。多张图片、视频及其他附件都保存为文件，不会自动打开。两端均需支持 0.2.0 文件协议；Windows 托盘须在当前桌面会话运行，显示保存完成回执才算成功。

## Windows 发送窗口自己关闭

手机确认全部文件保存成功后，窗口三秒自动关闭，这是正常行为。失败与取消提示不会自动关闭。要排查文件是否到达，应核对手机接收文件夹和保存回执，而不是仅看推送或 HTTP 是否返回成功。

提交反馈请附两端版本、网络类型和脱敏错误文字，不要附 DPAPI、接收 endpoint、私钥或真实剪贴板。
