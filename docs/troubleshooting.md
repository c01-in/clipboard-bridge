# 排查问题

## 没有推送或明显延迟

先区分三个阶段：Windows 提交 FCM、Android 完成写入、目标 App 实际粘贴。

- “已提交 FCM”只表示 Google 接受发送请求，不代表手机已经收到。
- “手机已确认”表示 Android 已执行剪贴板写入并回传确认。
- 在目标 App 粘贴是最后一步，尤其是图片。某些 App 只支持文字剪贴板。

检查手机的 Google Play 服务、联网情况和 App 通知权限。不要在系统设置中强行停止 App；若已停止，手动打开后恢复。三星等系统可能另外限制后台活动，可到本 App 的电池设置检查限制。

FCM 是按需唤醒通道，不提供每次即时到达保证。高优先级消息也会受系统、网络、配额和后台策略影响。

## 短文字成功，图片或长文字失败

短文字可直接装入加密推送；图片和较长文字需要从电脑下载。请确认手机可访问设置里的电脑地址和 TCP 45871。

- 同一局域网：检查 Wi-Fi 是否隔离客户端、电脑地址是否变化，以及防火墙规则。
- 跨网络：两端连接同一个可互通的 Tailscale 网络，并在 Windows 设置中填写 Tailscale 地址后重新配对。
- 默认不会向公网暴露下载端口，不要用直接公网端口转发作为排查方法。

## FCM 返回认证错误

检查服务账号 JSON 是自己的有效私钥、FCM HTTP v1 API 已启用、账号具有该项目的 FCM API 角色。`google-services.json` 与发送账号必须来自同项目，客户端包名必须匹配。

服务账号密钥被撤销后，重新生成并导入自己的新凭据。不要在公开 Issue 中上传 JSON 或复制完整服务器响应、配对链接、令牌。

## Windows 后台服务未启动

```powershell
Get-Service ClipboardBridge
Invoke-RestMethod http://127.0.0.1:45871/health
& "$env:ProgramFiles\ClipboardBridge\cli\ClipboardBridge.Cli.exe" status
```

检查安装时绑定的 Windows 用户是否就是当前使用托盘的用户。移动仓库或数据目录后，需要用新的 `-DataRoot` 路径重新运行安装脚本。不要删除 `local/runtime/` 来“清缓存”，这会丢失配对和发送凭据。

## 快捷键和剪贴板

- `Ctrl+Alt+V` 被其他程序占用时，可从托盘菜单手动发送。
- 自动同步会忽略上次成功提交过的同一内容；手动发送可再次发送。
- 原生图片、单个支持的图片文件和纯文字受支持；任意文件、多图或超过 16 MiB 的内容不支持。
- 系统会自行缓存 App 进程。“不常驻”指没有持续运行的接收前台服务，不表示每次接收后强行杀死进程。
